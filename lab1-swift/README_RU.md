# Лабораторная работа №1 — «Продвинутый калькулятор»

Это исходный проект **iOS-приложения на Swift и SwiftUI**, подготовленный по файлу `lab_1_advanced_calculator.pdf`. Проект включает интерфейс, независимый вычислитель выражений, историю из десяти записей, память, сохранение состояния и автоматические тесты. Внешние библиотеки и сетевое соединение для работы приложения не нужны.

## Нужно ли скачивать Swift?

**Если у вас Mac, установите Xcode, а не Swift отдельно.** Xcode включает инструменты разработки на Swift и позволяет запускать приложение в симуляторе iPhone. Саму среду можно скачать из [Mac App Store](https://apps.apple.com/app/xcode/id497799835). При первом запуске может потребоваться отдельно установить компоненты iOS и образ симулятора. [1] [2]

**Если у вас Windows или Linux, одной установки Swift недостаточно для запуска этого iOS-приложения.** Swift доступен для нескольких операционных систем, и вычислительную часть можно проверять вне macOS. Однако для сборки SwiftUI-интерфейса под iOS и работы с симулятором Apple нужен доступ к Mac с Xcode. В исходном задании разрешён также Flutter, но данный проект намеренно выполнен именно на Swift. [1] [3]

Проект рассчитан на **Xcode 15 или новее и iOS 16 или новее**. Совместимость устанавливаемой версии Xcode с вашей версией macOS проверяйте на странице Apple. Обновлять macOS только ради самой новой версии Xcode не обязательно, если уже имеется подходящая версия среды. [4]

## Как открыть и запустить на Mac

1. Установите Xcode и откройте его хотя бы один раз. Завершите установку предлагаемых компонентов iOS.
2. Распакуйте архив целиком. Не перемещайте файл проекта отдельно от остальных папок.
3. Откройте **`AdvancedCalculator.xcodeproj`** двойным щелчком. Для запуска приложения нужен именно этот файл, а не `Package.swift`.
4. В верхней части окна Xcode выберите схему **AdvancedCalculator** и устройство-симулятор iPhone с iOS 16 или новее. Не выбирайте `Any iOS Device` или `My Mac`.
5. Нажмите кнопку **Run ▶** либо **⌘R**. Дождитесь сборки и открытия симулятора.

Если симулятора нет в списке устройств, установите iOS Simulator Runtime через **Xcode → Settings → Components**; в некоторых версиях Xcode соответствующий раздел называется **Platforms**. После установки снова выберите виртуальный iPhone. [2]

Для запуска в симуляторе не требуется настраивать подпись приложения для физического iPhone. Если Xcode сообщает о необходимости выбрать `Development Team`, сначала убедитесь, что выбран именно симулятор. Для установки на настоящий iPhone настройка команды и подписи выполняется отдельно во вкладке **Signing & Capabilities**. [5]

## Что реализовано

| Требование задания | Реализация |
| --- | --- |
| Полное выражение, вещественные числа, скобки | Собственный лексер и парсер рекурсивного спуска |
| Операции `+`, `−`, `×`, `÷` и приоритет | Отдельные уровни разбора сложения и умножения |
| `=`, `C`, `⌫`, `%`, `±` | Кнопки интерфейса и действия бизнес-логики |
| История последних десяти вычислений | Новые успешные вычисления добавляются сверху; лишние удаляются |
| Повторное использование истории | Нажатие возвращает исходное выражение для редактирования |
| `M+`, `M−`, `MR`, `MC` | Добавление, вычитание, извлечение и очистка памяти |
| Сохранение при повороте | Модель принадлежит приложению через `@StateObject` |
| Восстановление после повторного запуска | Снимок состояния в JSON через `UserDefaults` |
| Ошибочные выражения без аварийного завершения | Типизированные ошибки и понятные сообщения на русском |
| Логика отдельно от интерфейса | Папка `Core` не импортирует SwiftUI и проверяется самостоятельно |

В снимке состояния сохраняются текущее выражение, история, память, последний успешный результат и сообщение об ошибке. Дополнительно сохраняется признак только что выполненного вычисления, чтобы после восстановления корректно работало продолжение результата.

## Как пользоваться

Выражение можно вводить кнопками калькулятора. Чтобы исправить текст в середине или вставить готовое выражение, нажмите на дисплей: откроется системная клавиатура. Экранные кнопки калькулятора добавляют символы **в конец** выражения. Кнопка «Готово» на дисплее скрывает системную клавиатуру.

Нажатие `=` вычисляет всё выражение и добавляет успешный результат в историю. Если затем нажать цифру, начнётся новое выражение; если нажать арифметический оператор, вычисление продолжится от результата. Кнопка `C` очищает текущий ввод, показанный результат и ошибку, но сохраняет память и историю. `⌫` удаляет один последний символ исходного выражения.

### Проценты

В задании не уточнено, должна ли операция процента зависеть от предшествующего сложения. В проекте выбран однозначный математический вариант: **`x% = x / 100`**. Поэтому `50% = 0.5`, `200 × 10% = 20`, а `200 + 10% = 200.1`. Чтобы прибавить к 200 десять процентов от него, введите `200 + 200 × 10%`.

Процент можно применять и к группе: `(20 + 30)% = 0.5`. Приложение не имитирует финансовую логику кнопки процента некоторых бытовых калькуляторов.

### Смена знака и отрицательные числа

Кнопка `±` меняет знак **последнего введённого числа или завершённой группы в скобках**. Например, введите `12 + 5`, нажмите `±`, затем `=`: результат будет `7`. Для сохранения приоритета приложение может показать служебные скобки: `12+(-(5))`. Повторное нажатие `±` снимает созданную обёртку.

Если результат уже вычислен, `±` переносит его в новый ввод с противоположным знаком; `=` завершает новое вычисление. Если выражение заканчивается оператором, сначала введите число, затем меняйте его знак.

Отрицательное число разрешено в начале выражения или внутри скобок: `−5 + 2`, `2 × (−3)`. Ввод `2 × −3` намеренно считается двумя арифметическими операторами подряд, поскольку задание требует обрабатывать этот случай как ошибку.

### Память

`M+` добавляет к памяти значение текущего корректного выражения, а `M−` вычитает его. Предварительное нажатие `=` не обязательно. После `=` используется последний вычисленный результат. Ошибочное выражение не меняет память.

`MR` вставляет число из памяти после оператора или открывающей скобки. В остальных случаях оно заменяет текущий ввод. Например, при памяти `5` ввод `2 ×` и нажатие `MR` дадут `2 × 5`. Отрицательное число после оператора подставляется в скобках. `MC` сбрасывает память в ноль.

### История и ориентация

В истории хранятся последние десять **успешных** вычислений. Нажмите запись, чтобы вернуть выражение. Кнопка «Очистить» в заголовке истории удаляет только историю.

На узком экране история находится под клавиатурой и доступна прокруткой. На широком экране она размещается справа. Поворот меняет компоновку, но не создаёт заново модель калькулятора.

## Ошибки и ограничения

Приложение различает пустой ввод, деление на ноль, ошибки скобок, два оператора подряд, несколько десятичных разделителей в одном числе и оператор в конце выражения. Также обрабатываются посторонние символы, отсутствие оператора между числами и переполнение числового диапазона. Ошибки не добавляются в историю.

Допускаются точка и запятая как десятичный разделитель, а также варианты `*`, `/` и `-` при ручном вводе. Неявное умножение не поддерживается: вместо `2(3+4)` нужно написать `2×(3+4)`. Экспоненциальная запись вида `1e-3` поддерживается, чтобы большие и малые результаты можно было использовать повторно.

Для вещественных вычислений используется `Double`. Это стандартная двоичная арифметика с конечной точностью; отображение ограничено 15 значащими цифрами. Это учебный калькулятор, а не инструмент точных финансовых расчётов. Ввод ограничен 1000 символами и 64 уровнями вложенности скобок, чтобы чрезмерно длинный текст не приводил к переполнению стека.

## Устройство проекта и объяснение для защиты

```text
AdvancedCalculator.xcodeproj/     Проект и общая схема Xcode
AdvancedCalculator/
  AdvancedCalculatorApp.swift    Точка входа и владение моделью
  Core/
    ExpressionEvaluator.swift    Лексер, парсер, ошибки, формат результата
    CalculatorSession.swift      Действия, история, память, смена знака
    StateStore.swift             Сохранение и восстановление состояния
  UI/
    CalculatorViewModel.swift    Связь бизнес-логики со SwiftUI
    CalculatorView.swift         Дисплей, кнопки, память, история
  Assets.xcassets/               Цвет интерфейса
Tests/CalculatorCoreTests/
  CalculatorCoreTests.swift       Автоматические тесты
Package.swift                    Независимая сборка и тестирование Core
```

**Лексический анализ** преобразует строку в последовательность токенов: чисел, операторов и скобок. После этого **рекурсивный спуск** разбирает выражение по уровням. Метод `expression()` обрабатывает сложение и вычитание, `term()` — умножение и деление, `primary()` — число либо выражение в скобках и постфиксный процент. Вложенное вычисление выполняется раньше внешнего; этим обеспечивается правильный приоритет без использования `eval` или `NSExpression`.

Например, при разборе `12+5×3` второй вызов `term()` сначала вычисляет `5×3`, и только затем `expression()` прибавляет результат к `12`. Для `(12+5)×3` метод `primary()` сначала вычисляет содержимое скобок.

`CalculatorSession` принимает действия пользователя и меняет `CalculatorState`. `CalculatorViewModel` публикует новое состояние через `@Published`, а SwiftUI перерисовывает представление. Вычислитель ничего не знает о кнопках и экране, поэтому его можно тестировать отдельно.

## Автоматическая проверка

В Xcode выберите симулятор и нажмите **⌘U**. В проект включена тестовая цель `AdvancedCalculatorTests`. Вкладка Test Navigator показывает результаты.

Другой вариант — открыть Terminal, перейти в распакованную папку проекта и выполнить:

```bash
swift test
```

Эта команда собирает только `Core` и его тесты, **не iOS-интерфейс**. Она также подходит для Linux с установленным Swift. Набор проверяет примеры из задания, приоритет, проценты, ошибочный ввод, историю, память, смену знака и восстановление состояния. Дополнительные проверки перебирают 100 сгенерированных корректных выражений и 1000 псевдослучайных строк.

**Граница проверки при подготовке:** доступная среда — Linux, без Xcode и Apple iOS SDK. Поэтому проверка вычислительного ядра не заменяет сборку приложения и визуальную проверку на симуляторе. Фактически выполненные проверки и их результаты приведены в `TEST_RESULTS.md`.

## Сценарий демонстрации преподавателю

| Действие | Ожидаемый результат |
| --- | --- |
| Ввести `12+5×3` и нажать `=` | `27` |
| Ввести `(12+5)×3` и нажать `=` | `51` |
| Ввести `15.5×2` и нажать `=` | `31` |
| Ввести `200×10%` и нажать `=` | `20` |
| Ввести `12+5`, нажать `±`, затем `=` | `7` |
| Очистить память, ввести `10`, нажать `M+`; ввести `3`, нажать `M−`, затем `MR` | Ввод и память равны `7` |
| Выполнить 12 вычислений | В истории остаётся 10 последних |
| Нажать запись истории и изменить выражение | Запись возвращается в редактируемый ввод |
| Ввести `1÷0`, `(2+3`, `2++3`, `1..2`, `2+`; каждый раз нажимать `=` | Понятное сообщение, приложение не закрывается |
| Нажать `C`, затем `=` | Сообщение о пустом выражении |
| Создать историю и память, получить ошибку, повернуть устройство | Выражение, память, история, результат и ошибка сохранены |
| Закрыть и снова запустить приложение после ввода | Сохранённое состояние восстановлено |

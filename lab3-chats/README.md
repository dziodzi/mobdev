# Лабораторная работа №3. Чаты

**Платформа:** iOS, **Swift + SwiftUI** (iOS 17+), Xcode 16 или новее. Сторонних библиотек нет.
**Сервер:** `http://faerytea.name:8008`

## Запуск
1. Открыть `lab3-chats/ChatsApp.xcodeproj`.
2. Схема **ChatsApp**, любой iPhone-симулятор → **⌘R**.
3. Тесты: **⌘U** (21 unit-тест, сервер не нужен — используется мок).

Bundle ID: `com.antondementiev.chatsapp`. Для учебного HTTP-сервера в `Info.plist` добавлено исключение App Transport Security только для домена `faerytea.name`.

## Структура
| Папка | Назначение |
|---|---|
| `ChatsApp/Core/Networking` | `ChatAPI` (протокол), `HTTPChatAPI` (URLSession + async/await), `APIError` |
| `ChatsApp/Core/Models` | `Message` (Codable), `OutgoingMessage`, `ChatRow`, `ChannelName` |
| `ChatsApp/Core/Storage` | Keychain (токен), черновики (UserDefaults, отдельно для каждого пользователя), кэш картинок |
| `ChatsApp/Session` | Состояние: `SessionStore` (вход/выход/401), `ChatSession` (каналы, выбранный чат, картинка), `ConversationStore` (сообщения, пагинация, отправка, черновик) |
| `ChatsApp/Features` | SwiftUI-экраны: вход, список чатов, переписка, просмотр картинки |
| `ChatsApp/Resources` | String Catalog (en + ru) |
| `ChatsAppTests` | Unit-тесты состояния, отправки, черновиков, 401, декодирования |

## Устройство состояния
- Все хранилища состояния — `@MainActor @Observable` классы. UI только читает их и вызывает методы.
- `SessionStore` создаётся один раз в `App`. Для каждого входа создаётся новый `ChatSession`. При выходе или ответе 401 он помечается недействительным, и ответы незавершённых запросов больше не попадают на экран.
- Для каждого канала создаётся свой `ConversationStore`, они кэшируются в `ChatSession`. Поэтому ответ от другого чата не может подменить сообщения текущего. Открытый чат, загруженные сообщения, черновик и позиция прокрутки (`scrollAnchor`) переживают поворот и смену раскладки.
- Загрузка запускается только из `loadInitialIfNeeded()` / `loadChannelsIfNeeded()` с проверкой статуса. Поворот и перерисовка запросов не делают.

## Черновики
- Черновик хранится отдельно для каждого канала (`[канал: ChannelLocalState]`) и для каждого пользователя (ключ `chats.local.v1.<логин>` в UserDefaults). Сохраняется автоматически при каждом изменении текста.
- При отправке текст переносится из поля ввода в элемент «Отправляется», который тоже сохраняется на диск. После подтверждения сервером он удаляется. Новый текст, набранный во время отправки, остаётся в поле.
- При выходе черновики пользователя удаляются. При истечении сессии (401) — нет, чтобы не потерять текст.

## Ошибки отправки
- Статусы сообщения: «Отправляется» → «Отправлено» / «Не удалось подтвердить отправку».
- При ошибке текст не теряется. Можно «Повторить» (обновляется тот же элемент, копия не создаётся) или «Вернуть в редактор».
- Автоматических повторов нет. Если запрос мог дойти до сервера (таймаут, обрыв связи, 5xx), перед ручным повтором показывается предупреждение, что сообщение могло быть доставлено.
- После успеха сообщение связывается с серверным `id`, и при обновлении истории дубликата не появляется.

# Лабораторная 3 — каналы на Flutter

Целевая платформа для сдачи: **Android**. Проект iOS создан, но требует macOS/Xcode для сборки и проверки. Идентификатор: `ru.itmo.student.channel_lab`.

## API

Используется официальный контракт https://faerytea.name/static/howto.md и пример https://faerytea.name/static/chat/app.html. Основной адрес по умолчанию — https://faerytea.name. Ссылки получены отдельно от растрового PDF. Для входа нужен существующий аккаунт сервера; регистрация пользователем доступна на https://faerytea.name/adduser.html. Регистрация не является функцией лабораторного приложения.

Для работы с официальным сервером после установки зависимостей: `flutter run` (без API_URL). Для контролируемой демонстрации сбоев есть локальный HTTP mock с теми же форматами запросов/ответов. Проверка сертификатов в приложении не отключена.

## Запуск

Нужны Flutter SDK (проверяется установленный 3.47.4, Dart 3.13.3), Android SDK, эмулятор Android, Python 3. Открыть терминал в этой папке.

```powershell
python tool/mock_server.py
```

В другом терминале:

```powershell
flutter pub get
flutter gen-l10n
flutter run --dart-define=API_URL=http://10.0.2.2:8080
```

`10.0.2.2` — хост для стандартного Android Emulator. Для телефона по USB можно выполнить `adb reverse tcp:8080 tcp:8080`, затем запустить с `--dart-define=API_URL=http://127.0.0.1:8080`. Для iOS Simulator используется localhost, но iOS здесь не проверен. Если flutter отсутствует в PATH, добавьте `C:\dev\flutter\bin` в PATH терминала.

Учётные записи mock: **alice / password**, **bob / password**. Пароль пользователя нигде не сохраняется. Сессия и черновики сохраняются через flutter_secure_storage.

```powershell
flutter analyze
flutter test
flutter build apk --debug --dart-define=API_URL=http://10.0.2.2:8080
```

Обычный HTTP разрешён в Android debug manifest для локального mock. Для релизного API нужен HTTPS. Если используете iOS, проверьте настройки Keychain signing в Xcode согласно документации flutter_secure_storage; гарантии сборки iOS в комплекте нет.

## Что реализовано

- Вход, скрытый пароль, блокировка повторного входа, отдельные ошибки сети/401/сервера.
- Сохранённая авторизация; выход с очисткой текущей сессии и черновиков пользователя.
- Каналы, загрузка, пустое состояние, повтор, pull-to-refresh и кнопка обновления.
- Сообщения, серверная пагинация по 20, загрузка предыдущих по кнопке, объединение по ID. Ошибка следующей страницы сохраняет историю.
- Текст, защищённые `/thumb/` и `/img/`, полный экран, загрузка/повтор и увеличение жестом.
- В портрете отдельный экран чата; в ландшафте список слева и чат справа.
- Выбранный канал, сообщения, черновик и смещение списка сохраняются при смене раскладки; открытая картинка остаётся открытой. Запросы идут из обработчиков и initState, а изображения используют кэш Future.
- Отдельные автоматические черновики для каждого пользователя и канала, восстановление после перезапуска. Отправленный текст удаляется только после подтверждения; новый текст, введённый во время отправки, сохраняется.
- У исходящего сообщения есть состояния отправки, подтверждения, неопределённого результата. При ручном повторе меняется тот же локальный элемент. Перед повтором показано предупреждение о возможном дубликате на сервере.
- Защита от ответов старой сессии и старого канала. Защищённый 401 завершает сессию один раз.
- ARB/gen_l10n, доступные подписи, прокрутка формы при клавиатуре, адаптация к увеличению текста.

Фоновая синхронизация, личные сообщения, регистрация и дополнительные функции не добавлялись.

## Проверка сценариев перед сдачей

Настройки `tool/mock_control.json` читаются на каждом запросе, перезапуск сервера не нужен. Верните все флаги в false после проверки.

1. Войти с неправильным паролем, затем alice/password. Во время загрузки повторный вход недоступен.
2. Открыть 1@channel, нажать «Предыдущие сообщения» дважды: 45 начальных сообщений без дублей. Прокрутить историю и повторить — текущая область не должна прыгать из-за добавления старых сообщений.
3. Повернуть устройство в чате и в просмотре градиентной картинки; проверить выбор, позицию и отсутствие повторных запросов. Картинка есть в сообщении 43.
4. Написать разные тексты в 1@channel и 2@channel. Закрыть приложение и открыть: восстановятся сессия и черновики (история и выбор канала после перезапуска не обязаны сохраняться).
5. Остановить сервер и отправить текст. Текст остаётся; виден неопределённый результат. Отдельно `lose_response: true` моделирует принятие сервером без ответа.
6. Вернуть сеть/сервер, отключить lose_response. Нажать повтор, прочитать предупреждение. Повтор обновляет одну локальную запись, но сервер может иметь две фактически принятые записи — это честно отражённая неопределённость API без идемпотентности.
7. Запустить mock с `--delay 3`, быстро переключать каналы во время загрузки. Старый ответ не должен заменить текущий чат.
8. `unauthorized: true` и обновление: экран входа, сессия очищена. `server_error: true` даёт ошибку сервера. `page_error: true` ломает только старые страницы. `empty: true` даёт пустой список каналов.
9. Выйти из alice, войти в bob: черновики alice недоступны. Возврат в alice после явного выхода тоже не восстановит удалённые черновики.
10. Проверить системный Android Back: картинка → тот же чат → список; в ландшафте Back закрывает выбранный чат. На корневом экране не выходит из аккаунта.
11. При отправке первого текста успеть набрать другой — новый черновик не должен исчезнуть. Проверить крупный системный шрифт и открытую клавиатуру.

Автотесты проверяют наиболее опасные переходы состояния. Перечень выше — сценарии ручной демонстрации, а не заявление, что они уже пройдены на физическом устройстве. Фактические результаты проверок — в `VALIDATION.md`.

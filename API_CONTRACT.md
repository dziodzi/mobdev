# Контракт API

Источник: https://faerytea.name/static/howto.md; поведение курсора сверено с https://faerytea.name/static/chat/chat.js. Основной адрес: https://faerytea.name.

| Метод | Путь | Формат |
|---|---|---|
| POST | /login | JSON {"name":"user","pwd":"password"}; ответ — токен plain text |
| GET | /channels | JSON массив строк имён каналов |
| GET | /channel/{name} | limit=20, lastKnownId={cursor}, reverse=true; ответ — массив сообщений |
| POST | /messages | JSON {"from":"user","to":"1@channel","data":{"Text":{"text":"hello"}}}; ответ — числовой id |
| POST | /logout | заголовок X-Auth-Token; забывает токен |
| GET | /thumb/{path} | байты миниатюры |
| GET | /img/{path} | байты полной картинки |

Токен передаётся через X-Auth-Token. Модель сообщения: id, from, to, data.Text.text либо data.Image.link, time. Имена/пути кодируются в URI, слеши пути картинки сохраняются. Клиент не реализует необязательные inbox, websocket, typing и отправку картинок.

Для самой новой страницы используется тот же верхний предел, что в клиенте-примере: 0xffffffffffff (281474976710655). Старые страницы запрашиваются относительно минимального ID загруженной страницы с reverse=true. Сообщения сортируются по числовому ID по убыванию. При странице короче 20 история закончилась; если записей ровно 20, возможен дополнительный запрос пустой страницы. Серверный массив объединяется по ID. Refresh получает новую верхнюю страницу, сохраняя ранее загруженные данные.

401 при входе — неверные данные; при защищённом запросе — завершение сессии. 5xx — ошибка сервера, ClientException/таймаут — соединение, неверное тело/прочие неуспешные статусы — протокол. Таймаут 15 секунд. POST не повторяется автоматически. Документация не обещает идемпотентность отправки, поэтому ручной повтор сопровождается предупреждением.

Mock соответствует этим форматам, но использует тестовую авторизацию alice/bob и хранит историю только в памяти. Он не предназначен для реальной переписки.
